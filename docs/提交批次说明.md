# 功能提交批次

项目此前在本地迭代，没有 Git 提交记录。本次按功能依赖整理为六个独立提交，使用本次整理的实际提交时间。中间版本是从当前代码按功能拆分并验证的版本，不代表原始开发时间线。

| 批次 | 提交标题 | 范围 |
|---|---|---|
| 1 | feat: 建立异常数据修复 Agent 基础工作流 | LangGraph 调查与诊断、Playbook 门禁、人工审批、版本复核、幂等与独立验收、CLI 和同步 API |
| 2 | feat: 接入历史修数经验 RAG 知识库 | JSON/JSONL 导入、中文 BM25 检索、历史引用与实时证据分离、查询 API、示例和测试 |
| 3 | feat: 增加五类只读平台模拟工具 | 日志、线上数据、配置中心、定时任务、Hive 快照，以及模型规划和工具查询 API |
| 4 | refactor: 通过封装后端接口执行修复 | 固定 HTTP 修复端点、结构化参数、幂等头、模拟业务后端、同源事实读取及超时结果未知处理 |
| 5 | feat: 增强 Agent 稳定性与长期运行能力 | 持久化队列、Worker、租约恢复、预算、取消、退避熔断、只读对账、输出归档、清理和监控 |
| 6 | docs: 完善中文使用指南与架构说明 | README、中文代码导读、架构说明和本批次记录 |

各批次包含相应测试；可通过 `git log --reverse --oneline` 查看顺序，通过 `git show <提交号>` 审阅某批变更。

虚拟环境、本地数据库、证据归档、缓存、系统文件及环境配置不纳入仓库。`examples/historical_cases.json` 和平台 fixtures 是可公开的模拟数据。

最终版本的验证命令：

```bash
python -m unittest discover -s tests -v
```

历史版本的同步 HTTP 创建与审批在第 5 批变为默认异步队列，返回 HTTP 202；`?wait=true` 保留同步演示入口。当前运行方式以 README 和稳定性文档为准。
