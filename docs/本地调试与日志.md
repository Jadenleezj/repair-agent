# Postman 本地调试与日志

## 启动与导入

在项目根目录运行：

```bash
source .venv/bin/activate
repair-agent-api
```

在 Postman 点击 Import，选择 `examples/repair-agent.postman_collection.json`。集合的 `base_url` 默认是 `http://127.0.0.1:8000`。

依次发送健康检查、创建工单、查看工单。创建成功会自动保存 `case_id`。异步执行需要重复查询详情；状态达到 `WAITING_APPROVAL` 后发送人工批准，再查询详情和时间线，确认修复与验收结果。批准会调用配置的修复后端；默认配置为空时使用本地模拟后端。示例 W1001 若已修复，应换未修复的演示订单，或在 Swagger 手动重置演示数据再测试。

## 日志位置

默认相对于启动目录，按上海日期分文件：

```text
logs/
  2026-10-13/
    agent.log    # 全部运行日志（含错误）
    error.log    # ERROR 及以上，包含异常堆栈
```

每行是一条 JSON，包含时间、级别、模块、线程，及可用的 `request_id`、`case_id`、`order_id`。HTTP 响应的 `X-Request-ID` 可以关联本次请求；后台任务用 `case_id` 关联。阶段开始、结束、耗时、状态，工具查询、模型调用、修复和验收都有日志。模型回退为 WARNING；等待审批是正常暂停。业务审计仍以 timeline 接口为准。

```bash
# 实时查看当天日志
 tail -f "logs/$(date +%F)/agent.log"
# 查询某个工单，包括审批前后
rg 'CASE-实际工单号' logs/
# 只查看异常
cat "logs/$(date +%F)/error.log"
```

在 `.env` 中可选配置：

```dotenv
REPAIR_LOG_DIR=logs
REPAIR_LOG_LEVEL=INFO
```

修改后重启服务生效。跨午夜会自动写入新日期目录；错误文件在首次错误时创建。日志不会自动删除，长期运行时可定期归档旧日期目录。`logs/` 已加入 Git 忽略；配置自定义目录时应另行添加忽略规则。

日志不记录用户完整描述、完整证据、模型提示词或返回正文。环境变量中的凭据及常见 Bearer/密钥字段会脱敏；对外分享日志前仍需检查订单编号及异常堆栈中的业务信息。
