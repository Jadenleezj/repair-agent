# 本地配置文件

项目启动时自动读取 `.env`，使用 [python-dotenv](https://github.com/theskumar/python-dotenv) 解析，不需要每次手动 export。

开发环境和 editable 安装固定读取项目根目录下的 `.env`；普通 wheel 安装读取启动目录下的 `.env`。也可以用 `REPAIR_ENV_FILE` 指定另一份文件，或在代码中调用 `load_local_config(path)`。

## 填写配置

本地已创建密钥留空的 `.env`。新环境中可从模板复制：

```bash
cp .env.example .env
```

如果已有自己的 `.env`，直接编辑已有文件。

填写下面三个值后启用真实模型：

```dotenv
REPAIR_LLM_BASE_URL=https://your-provider.example/v1
REPAIR_LLM_API_KEY=填写你的密钥
REPAIR_LLM_MODEL=填写模型名称
```

然后正常启动：

```bash
source .venv/bin/activate
repair-agent-api
```

CLI、Agent API、独立模拟后端、历史经验导入和直接创建 RepairRuntime 都会加载本地配置。模型配置未填齐时沿用规则推理。

数据库路径、知识库、后端接口密钥及运行预算也可以放在同一文件中，字段见 `.env.example` 和稳定性文档。数据库相对路径仍相对于启动目录。

## 优先级与修改生效

已有进程环境变量优先于 `.env`，文件中未定义的配置使用代码默认值。CLI 的显式 `--db` 参数优先于数据库环境配置。

每次启动会读取文件，已有运行进程不会热更新配置。修改模型、密钥或其他已有配置后，需要重启服务或重新运行命令。如果之前在终端 export 过同名变量，应先 unset 相应变量，或使用一个没有这些变量的新终端。

`.env` 缺失时默认配置仍可使用；显式指定的配置文件缺失会报错。

## 文件与密钥

`.env` 已被 `.gitignore` 排除，`.env.example` 只包含空值、默认值和注释。配置加载器不会输出密钥或文件内容，也没有提供返回完整配置的 HTTP 接口。创建本地文件时使用仅当前用户可读写的文件权限。

配置入口为 `repair_agent/application/config.py`。测试使用临时文件与模拟密钥，不请求真实模型服务。
